# thock closed beta — kit

Everything for a two-week beta with 5–10 people. Fill in the two
placeholders (download link, deadline), then send `invite.md`.

## Success criteria (decide before sending)

| Question | Bar |
|---|---|
| Can people install it without help? | ≥ 7 of 10 get to the first sound without asking you anything |
| Do they keep it? | ≥ 5 of 10 still have it running after two weeks (Launch at login on) |
| Does key force land? | ≥ 6 of 10 answer "yes, clearly" to "Do you hear the difference between light and hard?" |
| Why not Thock/Haptyk? | Every tester answers it; if most say "no reason", the positioning is wrong |
| Would they pay? | Informational only — the app stays free. Note what they'd pay *for* |

If the first bar fails, the install flow is the problem, not the app:
that is what the unnotarized path costs, and the moment to reconsider the
Developer ID.

## Files

- `invite.md` — message to send (chat, e-mail).
- `questionnaire.md` — five questions, ask after ~1 week and at the end.
- Log every reported problem as a GitHub issue with the label `beta`.

## Timeline

- Day 0: send invite + link.
- Day 2: ping the ones who haven't reported the first sound; ask what stopped them.
- Day 7: questionnaire round 1.
- Day 14: questionnaire round 2, close, write up results against the bars.
